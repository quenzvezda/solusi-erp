Goal: attempt safe, non-breaking fixes for common template-test failures.

Input: failing test diagnostics, context bundle, artifact_dir, run_id.

General fix strategies (in priority order):
1. Test fixture issues: repair or improve test setup (initialize missing beans, mock external services, fix data builders).
2. Missing or incompatible test data: add lightweight DTO/test factory fields or default values in test-only classes.
3. Flaky tests: increase timeouts, stabilize async waits, or isolate shared state.
4. Configuration problems: adjust application-test.properties or test slices (profiles, MessageSource, Locale) used only in tests.
5. Small production-safe changes: add null-safety guards or optional defaults that do not change public behavior (only if clearly non-breaking).
6. Test utility improvements: extend TemplateTestUtils / TestDtoFactory to better emulate app runtime for tests.

Procedure:
- Apply the candidate change locally in a branch and run targeted tests according to `test_scope` (changed/module/smoke preferred).
- Save a patch for any code changes: `git diff > {artifact_dir}\\{run_id}\\fix-{timestamp}.patch` and save logs to `{artifact_dir}\\{run_id}\\fix-{timestamp}.log`.
- Capture artifacts and diagnostics into `{artifact_dir}\\{run_id}\\` (mvn.log, surefire XML, stack traces, test-summary.json).
- If change appears non-invasive and tests pass for targeted scope, consider running a broader module/full test set before committing (per policy).
- If fix resolves failures, return patch summary and status 'fixed' and reference artifacts in the run folder.
- If fix is invasive or fails to resolve, mark status 'stopped' and surface patch + diagnostics for human review.

Safety & policy:
- Do NOT apply changes that alter production behavior without explicit human approval.
- If a fix touches production code beyond trivial guards or test-only utilities, require plan_approved checkpoint before committing.

Output: patch summary, status (fixed/stopped), and artifact references.
