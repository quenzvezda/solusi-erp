# JaCoCo Code Coverage — Implementation Guide

## Overview

Project ini menggunakan **JaCoCo 0.8.14** untuk mengukur code coverage dari unit tests. 
Coverage dijalankan secara otomatis setiap kali `mvn test` atau `mvn clean test` dijalankan 
dan menghasilkan laporan HTML dan XML.

---

## Versi dan Kompatibilitas

| Komponen | Versi |
|----------|-------|
| JaCoCo | **0.8.14** (rilis Oktober 2025) |
| Java | 21 |
| Spring Boot | 4.0.3 |
| Maven | 3.x |

**Mengapa 0.8.14?**  
JaCoCo bekerja di level JVM bytecode instrumentation — independen dari framework.
Versi 0.8.14 mendukung penuh Java 21–25 dan tidak ada breaking change di Spring Boot 4.x.
Spring Boot BOM tidak menyertakan JaCoCo, sehingga versi harus dideklarasikan eksplisit.

---

## Cara Menjalankan

```bash
# Run tests + generate coverage report
mvn clean test

# Lihat report HTML (buka di browser)
# target/site/jacoco/index.html
```

## Threshold Minimum

| Counter | Minimum | Status Saat Ini |
|---------|---------|----------------|
| **LINE** | 80% | Periksa laporan XML terbaru |
| **BRANCH** | 80% | Periksa laporan XML terbaru |

Konfigurasi: `<haltOnFailure>false</haltOnFailure>` — build **tidak gagal** meski threshold 
tidak terpenuhi, hanya warning. Ini sengaja agar CI tidak terganggu saat menambah fitur baru.

> Karena `<haltOnFailure>false</haltOnFailure>`, agent tetap wajib membaca warning dan laporan XML. `BUILD SUCCESS` saja belum membuktikan threshold terpenuhi.

## Strategi Exclude

### Prinsip Utama
Hanya kelas dengan **business logic yang bisa diuji secara unit** yang dimasukkan dalam coverage.
Kelas infrastruktur, DTO, dan generated code dikecualikan karena:
1. Tidak mengandung logika bisnis yang bisa gagal
2. Menurunkan angka coverage secara tidak adil
3. Lebih baik diuji via integration test atau contract test

### Tabel Exclude

| Pattern | Jenis Kelas | Alasan |
|---------|-------------|--------|
| `**/*Application*` | Spring Boot main class | Entry point, tidak ada logika |
| `**/config/**`, `**/*Config*` | `@Configuration` class | Hanya wire beans, bukan logika |
| `**/infrastructure/persistence/**` | JPA Entity + Spring Data repo | ORM mapping, generated by framework |
| `**/infrastructure/adapter/**/*RepositoryImpl*` | JPA repository adapter | Delegasi ke JPA, tidak ada logika domain |
| `**/infrastructure/adapter/**/*RepositoryAdapter*` | Security adapters | Delegasi ke use case / JPA |
| `security/**/*Filter*` | Spring Security filter | Infrastruktur request pipeline |
| `security/**/*Interceptor*` | HTTP interceptor | Infrastruktur web |
| `security/**/*AuthenticationSuccessHandler*` | Login handler | Infrastruktur security |
| `security/**/*UserServiceImpl*` | Spring Security `UserDetailsService` | Framework contract |
| `**/web/*ExceptionHandler*` | `@ControllerAdvice` | Error mapping, bukan logika bisnis |
| `**/*Request*`, `**/*Response*` | HTTP request/response DTO | Pure POJO |
| `**/dto/**`, `**/*Dto*` | Data Transfer Object | Pure POJO |
| `**/*Mapper*` | MapStruct mapper | Kode di-generate saat compile time |
| `**/model/AuditMetadata*` | Java record | Data holder |
| `**/model/Page*`, `**/model/Pageable*` | Pagination value object | Tidak ada logika |
| `**/model/DeleteResult*` | Enum | Tidak ada logika |
| `core/auditing/**` | JPA auditing | Framework infrastructure |
| `core/event/**` | Spring events | Framework infrastructure |
| `core/exception/DomainException*` | Exception class | Hanya field, tidak ada logika |
| `**/web/controller/**` | Spring MVC controller | Diuji via `@WebMvcTest` integration test |
| `**/web/template/**` | Thymeleaf template test | Diuji via template integration test |

### Kelas yang HARUS Punya Coverage (Primary Target)

| Layer | Contoh | Target Minimal |
|-------|--------|----------------|
| Use Case Impl | `DeleteTaxUseCaseImpl`, `BuildMenuTreeUseCaseImpl` | ≥ 80% |
| Domain Models | `StockBalance`, `Tax`, `StockAdjustment` | ≥ 90% |
| Domain Services | `FifoValuationService`, `ValuationLayer` | ≥ 80% |
| InUse Checkers | `GeographicInUseCheckerImpl`, `BrandInUseCheckerImpl` | ≥ 80% |
| Query Use Cases | `GetContainerLookupUseCaseImpl`, `SearchMenusUseCaseImpl` | ≥ 70% |

## Cara Membaca Report HTML

1. Buka `target/site/jacoco/index.html`
2. Klik nama package untuk drill-down ke kelas
3. Klik nama kelas untuk melihat line-by-line coverage
4. Warna:
   - 🟢 **Hijau** = baris ter-cover
   - 🔴 **Merah** = baris tidak ter-cover  
   - 🟡 **Kuning** = branch partial (sebagian cabang ter-cover)

## Cara Menambah Test untuk Coverage Baru

Saat menambahkan fitur baru, ikuti checklist berikut untuk memastikan coverage terjaga:

### Checklist per Fitur

```
[ ] Domain model test (semua method yang mengubah state)
[ ] Use case implementation test (happy path + error paths)
[ ] InUse checker test (jika ada Smart Delete)
[ ] Semua branch/kondisi if-else tercoverage
```

### Contoh: Use Case dengan Branching

```java
// Use case yang perlu ditest lengkap:
public class UpdateCurrencyUseCaseImpl {
    public Currency execute(Long id, ..., Boolean isDefault, ...) {
        // BRANCH 1: currency not found → test execute_throws_whenNotFound()
        Currency c = repo.findById(id).orElseThrow(...);
        
        // BRANCH 2: isDefault = true → test execute_unsetsOtherDefaults()
        // BRANCH 3: isDefault = false → test execute_skipsDefaultCheck()
        if (Boolean.TRUE.equals(isDefault)) { ... }
        
        return repo.save(c);
    }
}
```

Setiap `if`, `else`, dan `orElseThrow` adalah branch yang perlu test terpisah.

## Panduan Konfigurasi pom.xml

Jika perlu menambahkan kelas baru ke exclude list, tambahkan di **dua tempat** dalam 
`jacoco-maven-plugin`: execution `report` dan execution `check`.

```xml
<!-- Tambahkan di KEDUA execution: report dan check -->
<excludes>
    <!-- ... existing excludes ... -->
    <exclude>com/solusi/erp/**/your/new/package/**</exclude>
</excludes>
```

Pattern menggunakan format **class path** (bukan file path), dengan `/` sebagai separator
dan `*` / `**` sebagai wildcard.

## Catatan untuk Agent AI

Saat membuat fitur baru atau refactoring, perhatikan:

1. **Buat unit test untuk setiap use case** — terutama untuk semua branch (if/else/orElseThrow)
2. **Domain model test** — setiap method yang mengubah state harus di-test
3. **Jangan test kelas yang dikecualikan** — tidak perlu test RepositoryImpl, Config, DTO
4. **Ikuti naming convention** — `execute_throwsX_whenY()`, `execute_returnsX_whenY()`
5. **Run `mvn clean test`** setelah menambah test, pastikan BUILD SUCCESS dan tidak ada WARNING coverage

### Pola Test yang Direkomendasikan

```java
@ExtendWith(MockitoExtension.class)
@DisplayName("CreateXyzUseCase Tests")
class CreateXyzUseCaseImplTest {
    
    @Mock private XyzRepository repository;
    private CreateXyzUseCaseImpl useCase;
    
    @BeforeEach
    void setUp() { useCase = new CreateXyzUseCaseImpl(repository); }
    
    @Test
    @DisplayName("creates entity when input is valid")
    void execute_createsEntity_whenInputValid() { ... }
    
    @Test
    @DisplayName("throws DomainException when duplicate name")
    void execute_throws_whenNameAlreadyExists() { ... }
}
```

Gunakan `lenient()` untuk stub di `@BeforeEach` yang tidak selalu dipanggil
(menghindari `UnnecessaryStubbing` dari Mockito strict mode).
